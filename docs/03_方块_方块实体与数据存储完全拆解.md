# 03. 方块、方块实体与数据存储完全拆解

在写机器（比如制冰机、发电机、箱子）时，经常有人搞混 Block 和 BlockEntity，甚至把机器电量写成了“全世界机器共享”。这篇文档带你彻底吃透它。

---

## 一、Block vs BlockEntity（躯壳 vs 灵魂）

### 1. 什么是 Block？
在 Minecraft 里面，一个存档里有成百上千万个“泥土”或者“石头”。
如果每个方块都在内存里存一份独立的对象，你的电脑内存 1 秒钟就会被撑爆。
所以 Minecraft 采用了“享元模式”：
* 全世界所有的泥土，在 Java 内存里**只存在一个 `Blocks.DIRT` 单例对象**！
* 方块类 `Block` 只负责定义通用的物理属性：“这个方块有多硬？需要什么镐子挖？碰撞箱长什么样？踩上去有没有减速？”

> ⚠️ **新手致命大坑**：
> 如果你在 `Block` 类里声明一个普通变量：
> ```java
> public class IceMakerBlock extends Block {
>     public int currentEnergy = 0; // 💥 大祸临头！
> }
> ```
> 那么全世界所有的制冰机，**全都共用这同一个 `currentEnergy` 变量**！玩家在基地充了一台机器的电，千里之外荒野上的另一台机器也莫名其妙充满电了！

### 2. 什么是 BlockEntity（方块实体 / TileEntity）？
如果你需要方块**记住属于它自己的专属数据**（比如它肚子里装了什么物品、装了多少升水、充了多少电、工作倒计时还剩几秒），你就必须给它绑定一个 **BlockEntity**。
* 每个被放置在世界上的机器，在它所在的坐标 `(x, y, z)` 都有一个独一无二的 `BlockEntity` 实例。
* 它是方块的“大脑和仓库”。

## 二、机器界面的“三剑客”工作流

一个带界面的机器（比如我们的制冰机 `IceMaker`），由三个核心类协同工作：

```
+-------------------------------------------------------------+
|                     服务端 (Server)                          |
|                                                             |
|   IceMakerBlockEntity (数据核心：电量、液体槽、配方判定)        |
|             ▲                                               |
|             │ (通过容器数据 ContainerData 同步电量进度)          |
|             ▼                                               |
|   IceMakerMenu (服务端的逻辑菜单：管理物品槽位、接收点击)       |
+-------------┼───────────────────────────────────────────────+
              │ (Minecraft 网络自动同步槽位数据包)
+-------------┼───────────────────────────────────────────────+
|             ▼                                               |
|   IceMakerMenu (客户端的影子菜单：本地镜像数据)                 |
|             ▲                                               |
|             │ (渲染时读取当前物品与进度条数值)                  |
|             ▼                                               |
|   IceMakerScreen (客户端纯视觉界面：画贴图、画能量条、鼠标提示)  |
|                                                             |
|                     客户端 (Client)                          |
+-------------------------------------------------------------+
```

### 1. `IceMakerBlockEntity`（数据中心）
* 运行在服务端，负责执行 `tick()`：每 1/20 秒检查一次原料够不够、消耗电量、生产冰块。
* 负责把数据写入硬盘（`saveAdditional`），以及开服时从硬盘读回数据（`load`）。

### 2. `IceMakerMenu`（同步管道）
* 继承自 `AbstractContainerMenu`。
* 负责规定：哪个槽位是物品输入？哪个是输出？背包快捷栏在什么坐标？
* 玩家把鼠标上的物品放进槽位时，Menu 会向服务端发包验证。

### 3. `IceMakerScreen`（画面画师）
* 继承自 `AbstractContainerScreen<IceMakerMenu>`。
* **绝对不能出现在服务端！** 它只在客户端运行。
* 负责用 `GuiGraphics` 在屏幕上画出背景贴图、跳动的水面、闪烁的警示灯和文字提示。

## 三、数据的持久化（NBT 保存黄金法则）

当玩家退出世界、或者保存退出时，机器的数据必须写进世界文件夹（NBT 数据）。

### 黄金法则：写了什么，就必须读什么！
在 `BlockEntity` 中：
```java
// 1. 保存到硬盘
@Override
protected void saveAdditional(CompoundTag tag) {
    super.saveAdditional(tag);
    tag.putInt("Energy", this.energyStorage.getEnergyStored()); // 存电量
    tag.put("Inventory", this.itemHandler.serializeNBT());      // 存物品
    tag.put("Tank", this.waterTank.writeToNBT(new CompoundTag())); // 存流体
}

// 2. 从硬盘恢复
@Override
public void load(CompoundTag tag) {
    super.load(tag);
    if (tag.contains("Energy")) {
        this.energyStorage.setEnergy(tag.getInt("Energy"));     // 取电量
    }
    if (tag.contains("Inventory")) {
        this.itemHandler.deserializeNBT(tag.getCompound("Inventory")); // 恢复物品
    }
    if (tag.contains("Tank")) {
        this.waterTank.readFromNBT(tag.getCompound("Tank"));    // 恢复流体
    }
}
```
**千万不要在 `saveAdditional` 里存了一个键名叫 `"Energy"`，在 `load` 里却写成 `"energy"`（大小写不同），这样世界一重启，电量就会直接归零！**
