# 04. 着色器与渲染管线小白手册

你写了很酷炫的“维度裂缝”效果，用到了 Minecraft 的 Core Shader（核心着色器）技术。这个技术门槛比较高，我们把容易出事的盲区理清楚。

---

## 一、为什么光有 `.json` 游戏必报错？

在 Minecraft 1.17+ 引入 Core Shader 后，一个着色器必须由**三个文件共同组成**：

```
assets/fib_mod/shaders/core/
├── dimensional_crack.json  # 1. 配置文件（清单）：声明用哪些纹理槽（Samplers）、传哪些数值参数（Uniforms）
├── dimensional_crack.vsh   # 2. 顶点着色器（Vertex Shader）：算出模型四边形在屏幕哪个位置
└── dimensional_crack.fsh   # 3. 片元着色器（Fragment Shader）：算出每一个像素点画什么颜色
```

> 💡 **初中生生活比喻**：
> * `.json` 是**一张菜单**（上面写着：今天做番茄炒蛋，需要番茄、鸡蛋、糖、盐）；
> * `.vsh` 和 `.fsh` 是**真正的厨师和食材**。
> 如果你只把菜单交给了服务员（注册了 `dimensional_crack.json`），后厨却没有厨师和食材（缺失了 `.vsh` 和 `.fsh`），服务员一进厨房直接傻眼报警（抛出 `FileNotFoundException` / `IOException`），游戏当场报错。

所以，任何时候做自定义 Shader，必须保证这三兄弟整整齐齐都在！

---

## 二、`.vsh` 和 `.fsh` 各自负责什么？

### 1. 顶点着色器（`dimensional_crack.vsh`）
* **运行次数极少**：一个四边形只有 4 个顶点，所以这个程序只跑 4 次。
* **主要职责**：把三维世界里的坐标，通过矩阵运算变成你屏幕上的二维像素坐标：
  ```glsl
  gl_Position = ProjMat * ModelViewMat * vec4(Position, 1.0);
  ```
* 并把 UV 贴图坐标原封不动传给片元着色器。

### 2. 片元着色器（`dimensional_crack.fsh`）
* **运行次数极大**：屏幕上有 100 万个像素点覆盖了裂缝，这个程序就对每个像素点各跑 1 次！
* **主要职责**：决定每个像素的 `RGB + Alpha`。
  * 读取 Sampler0（星空贴图），根据玩家视角做出“视差 3D 深度”；
  * 读取 Sampler1（水波纹）和 Sampler2（闪电），算出裂缝边缘跳动的光效；
  * 如果算出来的距离在裂缝外面，直接 `discard`（丢弃这个像素，不画任何东西）。

## 三、两遍绘制与深度测试（Depth Test）的秘密

你在代码里写了：
```java
// 第一遍：实心层，写深度
shader.safeGetUniform("CrackMode").set(0.0F);
...
// 第二遍：边缘光晕，不写深度
shader.safeGetUniform("CrackMode").set(1.0F);
```
很多人不懂为什么要画两遍。

### 什么是深度（Depth）？
Minecraft 在画画面时，有个“深度缓冲本子”。如果一个像素离镜头只有 5 米（比如裂缝内部的星空），它就会在小本本上记下：`这个位置距离 5 米`。如果后面远处有只小猪（距离 10 米），小猪的像素就会被自动挡住不画。

* **如果实心层不写深度**：
  你站在裂缝前面，本来应该看到深邃的宇宙星空，结果裂缝背后 100 米外的一只牛透过星空浮现出来了（出现透视 Bug）！
* **如果边缘透明光晕写了深度**：
  透明的紫雾和光效如果在小本本上记了深度，光晕后面的人或者树就会被透明光晕给“挖空切掉”，看起来像穿模了一样。

所以**实心星空写深度、透明光芒不写深度**，分两遍绘制是完全正确的专业做法！
